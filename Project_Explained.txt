  PROJECT TITLE:
  Pakistani News Relevance Dashboard

  PROJECT OVERVIEW:
  This is an AI-powered multimodal news relevance analysis system. It scrapes
  news articles from two major Pakistani news sources — Dawn (English-language)
  and Daily Ummat (Urdu-language) — and uses a combination of Natural Language
  Processing (NLP) and Computer Vision techniques to find and rank articles that
  cover the same real-world events. The results are displayed through an
  interactive web-based dashboard with KPIs, charts, filters, and a sortable
  table.

  The system is divided into three major engineering roles:
    1. Data Engineer   — Web scraping, data storage, database, backend API
    2. ML/NLP Engineer — Text similarity, image similarity, matching pipeline
    3. Frontend Engineer — Dashboard UI, charts, interactivity, visual effects

  Each role has its own dedicated Git branch (data-engineer, ml-nlp-engineer,
  frontend-engineer) and the project is hosted on GitHub at:
  https://github.com/Jami436/pakistani-news-relevance-dashboard

  1.2.1 Dawn Scraper (scraper/dawn_scraper.py)
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  File: scraper/dawn_scraper.py — 133 lines

  WHAT IT DOES:
  Scrapes news articles from Dawn.com across 9 different sections:
    1. latest-news
    2. pakistan
    3. business
    4. world
    5. sport
    6. tech
    7. opinion
    8. culture
    9. prism

  For each section, it scrapes up to 10 pages of content.

  HOW IT WORKS (step by step):
  a) For each section, iterate pages 1 through max_pages_per_section (10).
  b) Construct the URL: https://www.dawn.com/{section} for page 1,
     https://www.dawn.com/{section}/{page} for subsequent pages.
  c) Send an HTTP GET request with a Chrome browser User-Agent header to
     avoid being blocked.
  d) Parse the HTML response using BeautifulSoup.
  e) Find all <article> tags with class="story" (Dawn's article container).
  f) For each article:
     - Extract the headline from the <a> tag's title attribute first,
       falling back to alt attribute, then the plain text.
     - Extract the article URL, normalizing relative URLs (starting with //
       or /) to absolute URLs.
     - Extract the image URL from the <img> tag, checking data-src,
       data-lazy-src, and src attributes (in that order), skipping
       data: URLs (inline base64 images).
     - Skip duplicate URLs using a seen_urls set.
  g) After collecting all raw articles, download images in parallel using
     25 concurrent worker threads via ThreadPoolExecutor.
  h) Save the final article list to SQLite database using insert_articles_batch.
  i) Export everything to data/raw/dawn_articles.csv for backup/reference.

  KEY DESIGN CHOICES:
  - Multi-section scraping ensures broad topic coverage (politics, business,
    sports, tech, culture, etc.)
  - Multi-page per section maximizes article count (up to 90 page loads).
  - Parallel image downloads with 25 workers makes image collection fast.
  - CSV export provides a human-readable, portable data backup.
  - URL deduplication prevents storing the same article twice.


  1.2.2 Daily Ummat Scraper (scraper/ummat_scraper.py)
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  File: scraper/ummat_scraper.py — 193 lines

  WHAT IT DOES:
  Scrapes news articles from Ummat.net (Urdu-language newspaper) using a
  two-phase approach: category pages + numeric ID archive crawling.
  Then translates Urdu headlines to English and filters out bad translations.

  HOW IT WORKS (5 phases):

  Phase 1 — Category Pages (10 categories):
     Categories: (empty/home), latest-news/, topnews/, national/,
     international/, sports/, commerce/, city/, literary/, editorial/
     For each category URL (https://ummat.net/{cat}):
     - Parse the HTML
     - Build a mapping from article URLs to their associated image URLs by
       scanning <a> tags containing <img> tags.
     - Find all heading tags (h1-h4) containing <a> links.
     - Extract headline text, article URL, and associated image URL.
     - Deduplicate by URL.

  Phase 2 — Numeric ID Archive Crawl:
     Ummat uses numeric IDs in URLs (e.g., https://ummat.net/991275/).
     The scraper starts from ID 991275 and crawls downward at high speed
     using 30 parallel worker threads.
     Each worker fetches a page, checks if it's a valid article (status 200,
     contains "ummat" in text, has a real headline > 5 chars, no "404" in
     title), and extracts headline and image.
     Continues until target_count (1200) articles are collected or IDs
     are exhausted down to ~980000.

  Phase 3 — Translation:
     Each Urdu headline is translated to English using Google Translate
     (via deep-translator library). Translations are cached to disk in
     data/raw/translation_cache.json to avoid re-translating on subsequent
     runs.
     Generic/failed translations (like "National", "Health", "Success
     stories", etc.) are filtered out to ensure quality.

  Phase 4 — Image Download:
     Images for all valid articles are downloaded in parallel using 25
     worker threads.

  Phase 5 — Database & CSV Save:
     Articles are saved to SQLite and exported to
     data/raw/ummat_articles.csv.

  KEY DESIGN CHOICES:
  - Two-phase scraping (categories + numeric IDs) ensures comprehensive
    coverage — categories give recent articles, numeric crawl gives
    historical depth.
  - 30 parallel workers for ID crawling makes this very fast despite
    thousands of HTTP requests.
  - Translation caching saves API costs and speeds up re-runs.
  - Generic title filtering removes failed/bad translations automatically.


  1.2.3 Scraper Utilities (scraper/utils.py)
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  File: scraper/utils.py — 111 lines

  Contains three utility functions shared across scrapers:

  translate_urdu_to_english(text):
  - First checks a local JSON cache (translation_cache.json) for existing
    translations to avoid re-translating.
  - If the text is already ASCII (English), returns it as-is.
  - Tries GoogleTranslator from deep-translator library first.
  - Falls back to the raw Google Translate API endpoint
    (translate.googleapis.com/translate_a/single) with up to 2 retry
    attempts.
  - If all translation attempts fail, returns the original text.
  - Saves cache to disk every 50 new translations to prevent data loss.
  - Returns the translated English string.

  download_image(url, filename):
  - Downloads a single image from a URL to data/raw/images/{filename}.
  - Skips data:image URLs (inline base64 images).
  - Skips download if file already exists (deduplication).
  - Sends a browser-like User-Agent header.
  - Returns the local file path on success, None on failure.

  download_images_parallel(image_tasks, max_workers=20):
  - Takes a list of (url, filename) tuples.
  - Downloads all images concurrently using ThreadPoolExecutor.
  - Returns a dictionary mapping URL -> local filepath.
  - Used by both Dawn and Ummat scrapers for fast image collection.

  1.4.2 Database CRUD Layer (backend/crud.py)
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  File: backend/crud.py — 242 lines

  Eight functions for database access:

  get_connection():
  - Creates and returns a new SQLite connection with Row factory enabled
    (so query results are accessible as dictionaries).
  - Uses a context manager (with statement) so connections auto-close.

  insert_article(article):
  - Inserts a single article into the database.
  - Catches IntegrityError for duplicate article_url (silently skips).
  - Extracts fields: source, headline, image_url, image_path, article_url.

  insert_articles_batch(articles):
  - Inserts multiple articles in a loop within a single transaction.
  - Returns count of successfully inserted articles.
  - Also catches IntegrityError for duplicates.

  get_all_articles():
  - SELECT * FROM articles — returns all articles as list of dicts.

  get_article_by_id(article_id):
  - Returns a single article by its primary key ID, or None if not found.

  get_articles_by_source(source):
  - Returns all articles filtered by source name (e.g., "Dawn" or "Ummat").

  get_stats():
  - Returns aggregated statistics:
    - total_articles, dawn_articles, ummat_articles
    - total_matches, high_matches, medium_matches, low_matches
  - Uses COUNT(*) queries on articles and matches tables.

  insert_match(match):
  - Inserts a match record with dawn_id, ummat_id, similarities, score,
    and match_level.

  get_all_matches():
  - Performs a JOIN query across matches and articles tables:
    SELECT m.dawn_id, d.headline AS dawn_headline, d.image_path AS dawn_image,
           m.ummat_id, u.headline AS ummat_headline, u.image_path AS ummat_image,
           m.text_similarity, m.image_similarity, m.relevance_score, m.match_level
    FROM matches m
    JOIN articles d ON m.dawn_id = d.id
    JOIN articles u ON m.ummat_id = u.id
    ORDER BY m.relevance_score DESC
  - Remaps local image paths to URL paths by extracting just the filename
    (os.path.basename) and prefixing with "/images/". This ensures the
    frontend can load images via the backend's static file mount.

  2.2 TEXT PREPROCESSING (ml_engine/preprocessing.py)
  ----------------------------------------------------
  File: ml_engine/preprocessing.py — 24 lines

  Function: preprocess_text(text) -> str

  WHAT IT DOES:
  Cleans raw article headlines before similarity computation.

  HOW IT WORKS (4 steps):
  1. Lowercase — converts all text to lowercase for case-insensitive
     comparison (e.g., "Pakistan" and "pakistan" match).
  2. Remove punctuation — regex [^\w\s] removes all non-word, non-space
     characters (periods, commas, quotes, etc.).
  3. Remove numbers — regex \d+ strips all numeric digits.
  4. Collapse whitespace — regex \s+ replaces multiple spaces with a
     single space, then trims leading/trailing spaces.

  WHY THIS MATTERS:
  Headlines from different sources may use different punctuation, case,
  and formatting. Normalizing them ensures the embedding model focuses on
  semantic content rather than surface-level formatting differences.


  2.3 TEXT SIMILARITY (ml_engine/text_similarity.py)
  ---------------------------------------------------
  File: ml_engine/text_similarity.py — 25 lines

  WHAT IT DOES:
  Computes semantic similarity between two article headlines using
  state-of-the-art NLP embeddings.

  MODEL USED:
  all-MiniLM-L6-v2 — A Sentence Transformer model that:
  - Is a distilled (smaller, faster) version of the BERT architecture
  - Produces 384-dimensional dense vector embeddings for sentences
  - Is optimized for semantic similarity tasks
  - Runs efficiently on CPU (no GPU required)
  - Is 5x faster than BERT while retaining good accuracy

  FUNCTION: calculate_text_similarity(text1, text2) -> float (0 to 1)

  STEPS:
  1. Preprocess both texts using preprocess_text().
  2. Encode each text into a 384-dimensional embedding vector using the
     SentenceTransformer model (model.encode([text])).
  3. Compute cosine similarity between the two embedding vectors using
     sklearn.metrics.pairwise.cosine_similarity.
  4. Return the similarity score rounded to 3 decimal places.

  COSINE SIMILARITY FORMULA:
    similarity = (A . B) / (||A|| * ||B||)
    where A and B are embedding vectors, . is dot product, || || is
    vector magnitude.

  Values range from -1 (opposite meaning) to 0 (unrelated) to 1 (identical
  meaning). Since our embeddings are positive, results are typically 0 to 1.

  GLOBAL MODEL LOADING:
  The SentenceTransformer model is loaded at the module level (line 6),
  which means it loads once on import and is reused across all function
  calls. This is critical for performance — loading the model takes several
  seconds but encoding takes milliseconds per text.


  2.4 IMAGE SIMILARITY (ml_engine/image_similarity.py)
  -----------------------------------------------------
  File: ml_engine/image_similarity.py — 97 lines

  WHAT IT DOES:
  Compares two article images using TWO complementary techniques:
  1. Difference Hash (dhash) — measures structural/perceptual similarity
  2. HSV Histogram Correlation — measures color similarity

  WHY TWO TECHNIQUES?
  - dhash captures layout/structure similarity (e.g., both photos show a
    person at a podium).
  - HSV histogram captures color palette similarity (e.g., both photos
    have blue sky and green grass).
  - Combining them gives a more robust similarity measure than either alone.

  IMAGE SIZE FILTER:
  Images smaller than 5000 bytes (5KB) are automatically filtered out
  with a similarity score of 0. These are usually logos, icons, or
  placeholder images that don't represent article content.

  2.4.1 Difference Hash (dhash)
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  Function: dhash(image, hash_size=8) -> list of booleans
  Function: dhash_similarity(img1, img2) -> float (0 to 1)

  HOW DHASH WORKS:
  1. Convert image to grayscale.
  2. Resize to (hash_size + 1) × hash_size pixels (9x8 by default).
  3. Compare each pixel with its neighbor to the right.
  4. If left pixel is brighter than right pixel, the bit is 1, else 0.
  5. This produces a 64-bit "fingerprint" of the image (8 rows × 8 cols).
  6. Compare two hashes using Hamming distance (count of differing bits).
  7. Similarity = 1 - (Hamming distance / 64).

  WHY DHASH:
  - Very fast (pure Pillow, no heavy libraries).
  - Robust to resizing, aspect ratio changes, and minor color variations.
  - Captures the "structure" of an image — two photos of the same event
    will have similar gradients.

  2.4.2 HSV Histogram Correlation
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  Function: histogram_similarity(img1_path, img2_path) -> float (0 to 1)

  HOW IT WORKS:
  1. Load both images using OpenCV (cv2.imread).
  2. Convert from BGR to HSV color space.
  3. Compute a 2D histogram on Hue (180 bins) and Saturation (256 bins)
     using cv2.calcHist.
  4. Normalize both histograms to [0, 1] range.
  5. Compare using HISTCMP_CORREL (Pearson correlation).
  6. Scale the correlation from [-1, 1] range to [0, 1] range using
     formula: max(0.0, (correlation + 1.0) / 2.0).

  WHY HSV:
  - HSV (Hue, Saturation, Value) separates color from brightness, making
    it more robust to lighting changes than RGB.
  - Two images of the same event (e.g., a cricket match) will have similar
    color distributions (green field, white clothing, red/white ball).

  2.4.3 Combined Score
  ~~~~~~~~~~~~~~~~~~~~~
  Function: calculate_image_similarity(image1_path, image2_path) -> float

  Score = 0.50 × dhash_similarity + 0.50 × histogram_similarity

  Equal weighting gives both structure and color equal importance.
  Returns 0.0 if:
  - Either image path is None or empty
  - Either image file doesn't exist on disk
  - Either image is smaller than 5KB (logo/placeholder filter)
  - Any exception occurs during processing


  2.5 RELEVANCE SCORING (ml_engine/scoring.py)
  ---------------------------------------------
  File: ml_engine/scoring.py — 31 lines

  Function: calculate_relevance(
      headline1, headline2, image1_path, image2_path,
      text_weight=0.65, image_weight=0.35
  ) -> dict

  WHAT IT DOES:
  Combines text and image similarity into a single multimodal relevance
  score using weighted averaging.

  SCORE FORMULA:
    relevance_score = 0.65 × text_similarity + 0.35 × image_similarity

  WHY THESE WEIGHTS:
  - Text (65%): Headlines are the primary indicator of topic. If two
    articles' headlines are semantically similar, they likely cover the
    same event. This is especially important because we're matching
    cross-lingual content (English vs translated Urdu).
  - Image (35%): Images provide supporting visual evidence but can be
    misleading (e.g., generic stock photos). The lower weight prevents
    false positives from coincidentally similar images.

  Returns a dictionary with keys:
  - text_similarity: float (0-1)
  - image_similarity: float (0-1)
  - relevance_score: float (0-1)


  2.6 ARTICLE MATCHING PIPELINE (ml_engine/matcher.py)
  -----------------------------------------------------
  File: ml_engine/matcher.py — 213 lines

  This is the CORE of the ML system — it matches Dawn articles with Ummat
  articles covering the same real-world events.

  FUNCTION: match_articles() -> list of match dicts

  HOW IT WORKS (step by step):

  Step 1 — Data Loading:
  - Connect to the SQLite database.
  - Query all Dawn articles (source = 'Dawn'): SELECT id, headline, image_path
  - Query all Ummat articles (source = 'Ummat'): SELECT id, headline, image_path
  - Close database connection.
  - If either set is empty, print error and return.

  Step 2 — Batch Embedding (Vectorization):
  - Preprocess all Dawn headlines and all Ummat headlines using
    preprocess_text().
  - Encode ALL Dawn headlines simultaneously using model.encode() with
    batch_size=64 and show_progress_bar=True.
  - Encode ALL Ummat headlines simultaneously the same way.
  - This produces two matrices:
      Dawn Embeddings:  (N_dawn × 384)
      Ummat Embeddings: (N_ummat × 384)

  Step 3 — Cosine Similarity Matrix:
  - Compute the full similarity matrix using sklearn's cosine_similarity:
      sim_matrix[N_dawn x N_ummat]
  - Each cell [i][j] contains the cosine similarity between Dawn
    article i and Ummat article j.
  - This vectorized approach is MUCH faster than comparing pairs in a loop.

  Step 4 — Candidate Filtering (for each Dawn article):
  - Find all Ummat indices where sim_matrix[idx_d] >= MIN_TEXT_FILTER (0.20).
  - Filter out "generic" headlines that are bad translation results
    (e.g., "National", "Health", "Success stories", etc. — these come
    from when Google Translate fails on short Urdu titles).
  - If no candidates remain, skip this Dawn article.

  Step 5 — Top Candidate Selection:
  - Sort candidates by text similarity score (descending).
  - Take only the top MAX_IMAGE_CANDIDATES (5) candidates for image
    similarity computation (computing image sim is expensive — it requires
    loading and processing image files).
  - For each top candidate:
    a) Compute image similarity using calculate_image_similarity() if both
       images exist on disk.
    b) Compute combined relevance: 0.65×text_sim + 0.35×image_sim.
    c) Track the best (highest relevance) candidate.

  Step 6 — Save Best Match (if qualifying):
  - If best candidate exists AND:
      text_similarity >= MIN_TEXT_SAVE (0.25)
      relevance_score >= MIN_SCORE_SAVE (0.30)
  - Classify match level:
      >= 0.50 → "High"
      >= 0.38 → "Medium"
      < 0.38  → "Low"
  - Check if this (dawn_id, ummat_id) pair already exists in matches table
    to avoid duplicates.
  - Insert match record via insert_match().
  - Append to best_matches list.

  Step 7 — Return Results:
  - Sort all matches by score descending.
  - Close database connection.
  - Print summary statistics.
  - Return the list of best matches.

  MATCHING THRESHOLDS SUMMARY:
  ┌─────────────────────────┬──────────┐
  │ Parameter               │ Value    │
  ├─────────────────────────┼──────────┤
  │ MIN_TEXT_FILTER         │ 0.20     │
  │ MIN_TEXT_SAVE           │ 0.25     │
  │ MIN_SCORE_SAVE          │ 0.30     │
  │ HIGH_THRESHOLD          │ 0.50     │
  │ MEDIUM_THRESHOLD        │ 0.38     │
  │ TEXT_WEIGHT             │ 0.65     │
  │ IMAGE_WEIGHT            │ 0.35     │
  │ MAX_IMAGE_CANDIDATES    │ 5        │
  └─────────────────────────┴──────────┘

  Generic headlines filtered:
  {"National", "Health", "Success stories", "Ummat literature",
   "Surprise", "Bam world", "Environmental variation",
   "Colors of the universe"}

  2.8 KEY DESIGN INSIGHTS ABOUT THE ML APPROACH
  ----------------------------------------------

  CHALLENGE: CROSS-LANGUAGE MATCHING
  Dawn articles are in English. Ummat articles are in Urdu, translated
  to English via Google Translate. The translations are imperfect.
  Solution: all-MiniLM-L6-v2 produces embeddings that capture semantic
  meaning, not exact wording. Even imperfect translations of the same
  event will have similar embeddings.

  CHALLENGE: PERFORMANCE
  N_dawn × N_ummat comparisons would be O(n^2) if done naively.
  Solution: Vectorized similarity matrix computation (Step 3) and top-5
  candidate filtering (Step 5) reduce image similarity computations from
  potentially millions to just N_dawn × 5.

  CHALLENGE: IMAGE QUALITY VARIATION
  News websites use various image sizes, formats, and quality levels.
  Solution: dhash is robust to resizing; HSV histogram is robust to
  lighting changes; 5KB minimum filter removes logos/placeholders.

  CHALLENGE: FALSE POSITIVES FROM TRANSLATION
  Failed translations often produce generic single-word results.
  Solution: The generic headlines set explicitly filters these out before
  computing expensive image similarity.

================================================================================
  HOW TO RUN THE PROJECT
================================================================================

  1. Install dependencies:
     pip install -r requirements.txt

  2. Start the backend:
     uvicorn backend.main:app --reload
     → Runs on http://127.0.0.1:8000

  3. Start the frontend:
     cd frontend_UI
     python -m http.server 5500
     → Runs on http://127.0.0.1:5500

  4. (Optional) Run the full data pipeline:
     python run_full_scraper.py

  5. (Optional) Re-run matching only:
     python rematch.py
